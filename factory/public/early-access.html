Merge Proof Early Access

This page is for people who received a direct invitation. It is not a public offer.

Merge Proof checks whether the available GitHub evidence actually supports the exact candidate being merged, and keeps a receipt of what it could establish. Early Access is a small, deliberately limited pilot: 20 invited accounts. We want to know where the product is confusing, where the evidence is thinner than you expected, and where it gets in your way.

What you receive

  • 10 calendar days of hosted, report-only access. No card, and no automatic charge when it ends.
  • Your 10 days are assigned to the GitHub account that owns the installation, from a server-side invitation list. If your account is not on that list you get the ordinary public offer of 7 days instead — nothing on this page changes that.
  • The clock starts with your first successful hosted proof: a CURRENT, collection-complete VERIFIED or NOT_PROVEN receipt. Connecting GitHub, installing the App, authorizing repositories, historical scans, FAIL results and unavailable or stale collection do not start it.
  • One trial per GitHub account, shared across that account's installations. Reinstalling does not restart it.
  • After Early Access, Pro is US$29/month per active developer. Choosing not to continue simply pauses new hosted proofs, re-proofs and scans.

Install it

  1. Connect GitHub at merge-proof.ohcaygo.com/proof/. You will need a GitHub account and a repository you can authorize.
  2. Install the App on the repositories you choose. It requests read permissions for the evidence it reads, plus Checks write solely to publish the receipt Check. It never requests Contents write, secrets, or organization administration.
  3. Open or point it at a PR. Merge Proof discovers open pull requests automatically and watches for the next one if none is open. You can close the page; it keeps working.
  4. Read the receipt. The receipt Check appears on the PR in GitHub. The account view at /proof/ shows the same observations with the explanation, the evidence gap and the next action.

Nothing in this flow changes your repository. Merge Proof never edits branch protection or rulesets, and Early Access does not enable any enforcing gate — new enforcement requires paid Pro and a repository administrator acting inside GitHub.

What to expect from the results

NOT_PROVEN is normal and is not a criticism of your code. It means Merge Proof could not establish everything it needs from the evidence GitHub actually exposed — missing, ambiguous, unsupported or unavailable. Please report these rather than assuming they are bugs; which gaps you hit most is exactly what we need to learn.

  • VERIFIED — for a CURRENT receipt, the available evidence satisfied the implemented checks for that exact observed state. It is not a correctness or security guarantee.
  • FAIL — sufficiently bound evidence showed a required condition was unmet.
  • STALE — something relevant changed after the receipt was issued. The original verdict is preserved; freshness is reported separately.

Known limitations during Early Access

We would rather you read these here than discover them mid-pilot.

  • This is not a certified release. Merge Proof's internal Level 3 assurance programme is explicitly not complete, and Early Access does not claim it is. Independent portable verification, signed evidence replay and recovery drills have been exercised in a lab; they have not been certified on the production host.
  • Hosted receipts are not cryptographically signed. The signer is implemented and lab-proven, but no production signing key is in service, and no public key set has been published. Treat an Early Access receipt as an inspectable record, not as an independently attestable one.
  • No availability, recovery or retention commitment. The service runs on a single host with a single writer. Backups exist, but the internal 15-minute recovery-point and 4-hour recovery-time objectives are unmet and unmeasured on production infrastructure. Do not make Early Access receipts your only copy of anything, and expect occasional planned pauses.
  • Evidence coverage is bounded. Code-coverage aggregates are not collected at all: GitHub does not yet expose an aggregate with the provenance required, so coverage claims stay NOT_PROVEN. CODEOWNERS requirements, last-push approval rules, exempt bypass actors, merge-queue sibling entries and some rebase and squash histories are explicitly unsupported.
  • A receipt is a point-in-time observation, not an atomic merge decision. GitHub can accept a merge in the window between an observation and its publication. Keep GitHub's own head-SHA guard and required checks.
  • Your repository metadata is stored. Paths, identifiers, SHAs, normalized checks and rules are retained to produce and refresh receipts. Merge Proof does not clone your repository tree, execute your code, or send your code to a model. See the Privacy Policy.
  • No AI model decides a verdict. The verdict is deterministic.

Sending feedback

Email support@ohcaygo.com with “Early Access” in the subject, or open an issue at github.com/ohcaygo/merge-proof/issues. Reach ryan@ohcaygo.com directly if support is unreachable.

Useful things to include: the repository and PR you were looking at, the receipt ID, what you expected the result to be, and what you would have done next. Never send access tokens, private keys or credentials. If something looks like a security issue, please follow SECURITY.md instead of opening a public issue.

You can stop at any time: uninstall the App in GitHub. That halts new proofs and revokes hosted receipt access, and changes nothing else in your repository.
