## Implemented preparation

- `enhanced-policy.js` uses existing authenticated customer/repository authority, explicit admin consent, immutable account/installation/repository IDs, single-use session-bound installation state, and server-side installation discovery. The UI identifies the optional powerful permission, access state and opt-out/removal distinction. Capability availability is never a proof verdict.
- `policy-broker.js` owns the companion key in a separate UID/process and accepts only bounded structured Unix-socket messages. Fixed GitHub policy GETs and token lifecycle operations are the entire credential interface. Mutations and arbitrary URLs are rejected before provider requests. Proof configuration contains public App routing and IPC paths only. Root-owned systemd templates block workload IMDS access and hide the other workload's credentials. The startup rejects a declared shared proof/broker UID. Linux process acceptance and actual EC2 isolation are distinct checks.
- Consent, uninstall, suspension, selected-repository removal and observed policy access loss invalidate/requeue dependent claims. New policy observations compare the existing per-claim bindings; independent target/approval facts do not get refreshed or invalidated by an execution-policy observation. Unchanged receipt bodies remain historical. Provider rules/events are GitHub-observed; unknown inherited details and qualifying coverage evidence remain NOT_PROVEN.
- Mirrors retain exact base/head/provider candidate/queue input refs before later fetches or GC. Old archives keep their frozen policy engine and signed provenance. This extends object retention without weakening the reconstruction envelope.
- `backup.js` exports atomic proof state plus checked immutable receipt/merge/landing/index/operator-log closure; optionally captures the separate factory state and its referenced completed reports. Existing mirror locks fence concurrent Git work. No service configuration is included. Immutable source files use same-filesystem links where possible; other files stream-copy/hash. Cross-mount copies need temporary storage headroom. Restore creates a new destination and preserves historical status.
- `backup-cycle.js` uploads content-addressed objects with provider checksum/version readback, copies them across account/region, and confirms the recovery manifest by retrieval using the recovery identity. Recovery uses pinned object versions and needs no primary credential. `verify-restored.js` verifies receipts/landings with independently supplied public trust and recomputes every retained reconstruction claim using its original pinned Git binary. A missing old runtime or object is a failed acceptance, not a passing restore.
- `accept-signer.js` binds the selected account, key ARN/specification/usage, public key and short-lived runtime role, exercises the existing KMS adapter, and prepares **unpublished** JWKS. A challenge is not a production receipt acceptance.
- `object-lock-lab.js` only accepts tagged disposable buckets in different accounts/regions. It tests write, unlocked control deletion, COMPLIANCE readback, protected-version deletion and shortening refusal, cross-account copy, independently read recovery bytes, post-retention deletion, and actual lifecycle version absence. `finish` stays NOT_PROVEN while provider expiration is pending. It never enables production retention.
- `refresh-credentials.js` materializes private per-UID Secrets Manager configuration and temporary STS sessions in root-owned, non-workload-writable `/run` directories; the companion receives no AWS/signing credential. The credential timer renews before expiry. App-secret changes need a controlled process restart; they are not silently activated by rewriting configuration.
- Prepared timers cover five-minute backups, daily seven-daily/four-weekly EBS snapshot retention, monthly isolated restores, minute-level CloudWatch health, and temporary credential renewal. Receipt-signing failures are tracked independently of whether an earlier daily checkpoint exists; only a successful signer call clears that alarm. Snapshot ACK/pending is not a completed snapshot. Snapshots are a secondary crash-consistent recovery mechanism; cross-account S3 is the independently checked recovery path.
- `lab/run.js` accepts only explicit repository/owner-ID allowlists for the new organization. `lab/scheduled.js` and the inactive private workflow template bind the immutable source SHA, selected standard lab App installations and bounded observer runs. Weekly Sunday 14:17 UTC, one job, 20-minute cap, 30-day private artifacts. Model/producer/currentness/OS-isolation tests accompany provider observations. Read-mode cohorts preserve NOT_PROVEN; signed positive queue acceptance remains a separately driven real provider journey.
