# Authorization and data-handling truth

**Observed:** 2026-09-29

**Scope:** current hosted Early Access implementation and public GitHub App `ohcaygo-merge-proof`

**Authority:** implementation, tests, current provider metadata, and current operations records. This is not a promise that GitHub or a future release cannot change; re-read provider and deployed configuration before a release claim.

## Current provider grant

The public GitHub App reports repository permissions `actions: read`, `administration: read`, `checks: write`, `contents: read`, `merge_queues: read`, `metadata: read`, `pull_requests: read`, and `statuses: read`, plus organization `members: read`. The OAuth login request supplies no `scope` parameter. Repository installation tokens are further requested for one exact repository ID in `github/app.js`.

The optional Enhanced Policy Proof companion is separate. If a customer explicitly enables it, GitHub grants that companion repository Administration write, while the isolated broker constrains product operations to policy reads. That provider grant is broader than the standard App and must not be described as read-only. It is not part of the standard connection.

## Supported public claims

- GitHub does not grant the standard Merge Proof App Contents write authority.
- The standard App cannot push commits, change branches or files, merge/close PRs, post PR comments, alter repository settings or branch rules, or modify Actions workflows through its current permissions.
- Contents read is real source access. Bounded workflow text, API patch text, and Git objects may reach the server.
- Deterministic reconstruction uses a private partial bare mirror and retains exact Git objects for replay; customer code is not executed.
- Receipt evidence contains sensitive repository metadata and retained Git objects. This is not a “no customer data” product.
- Incidental workflow/patch text is not persisted in receipts. Normalized paths, identities, hashes, checks, reviews, rules, actors, currentness, and merge/landing evidence are persisted.
- Source contents are not sent to an LLM or AI provider, and no AI model decides the verdict.
- Uninstall/revocation stops new work and access fails closed; it does not automatically erase retained evidence or backups.
- Private proof access follows current repository authorization. It is not anonymous and it is not necessarily limited to a single billing owner when multiple people are legitimately authorized to the same repository.

## Known concern and disposition

The prior homepage sentence “It does not clone a repository tree” understated current reconstruction. The amended buyer copy now discloses the private partial bare mirror and retained Git objects. No unexpectedly broader standard GitHub permission, customer-repository content write path, model transmission path, public credential exposure, or unrelated-customer access path was established in this review.
